# v1.1.13 - Independent Repeated Ads and Sidebar Placements

## Changes

- Fix ordinary identical advertising snippets rendering only in the top placement. Automatic mode plans every enabled visible slot before execution and gives repeated script snippets independent iframe documents, including deferred result and sidebar placements. This prevents shared IDs, singleton globals and top-level constant declarations from interfering across slots.
- Preserve explicit inline mode and recognize common AdSense/GPT patterns as page-integrated SDKs. Recognition is heuristic, not a provider compatibility guarantee. Providers can still require different unit IDs or decline repeated-unit delivery.
- Restore parser order for script-only/document.write/atOptions legacy loaders inside compatibility iframes. Preserve asynchronous behavior for native widgets with a DOM container, including snippets with the script before the container.
- Add independent left and right sidebar placements throughout defaults, validation, authenticated save/reload, public configuration and frontend rendering. Existing configurations retain their values; new sidebar placements default to disabled.
- Display sidebars only at viewport widths of at least 1500px, outside the centered content. Each side supports independent dismissal, bounded scrolling and a 160-280px width. Prefer 160x600 or responsive vertical creatives. Narrow screens do not initialize pending sidebar scripts; widening initializes them once. Dismissal lasts until refresh.
- Keep result advertisements deferred until successful query results are visible. Queries, language/theme changes and resizing do not rerun initialized slots. Expose mode and isolation reason through container diagnostic attributes.
- Update package version and local asset cache parameters together. No production dependency changes or compilation pipeline are introduced.

## Functional Evidence

The development implementation completed **6 Node interface/configuration tests and 19 Playwright browser tests**. Coverage includes the full administrator-save/public-API/frontend chain, old settings migration, six simultaneous copies of a singleton snippet, duplicate JavaScript constants, legacy async document.write, native async script-before-container behavior, explicit inline/main-page SDK preservation, disabled duplicate configurations, delayed results, sidebar viewport thresholds/no overlap, independent close and theme/language persistence.

Tests use disposable copies with dummy settings and mocked network responses; they do not modify real configuration. Desktop and narrow-mobile demonstration screenshots were visually inspected. The functional tests ran before the final version/cache/documentation-only edits. No live advertising provider or user-supplied snippet was tested, and successful script loading does not prove provider fill.

## Review and Security Limits

The v1.1.13 advertising diff was checked by source inspection for authenticated persistence, validation, fixed-field public projection, migration, trusted script execution and iframe message-source binding. This is focused development review, not a new complete independent security audit or a penetration test. The previous v1.1.12 audit remains a quick, partial source-only pass; its coverage must not be extended to this diff or to the whole product.

The OS-enforced isolated runtime security environment remains unavailable. No target execution was performed as security validation. Existing authentication/password lifecycle, updater internals, global pre-authentication 2MiB JSON-parser capacity, deployment TLS/proxy/CSP and provider policies are not cleared by this release.

Production dependency versions are unchanged. The previous dependency scan reported **four transitive advisories: body-parser (low), qs (moderate), path-to-regexp (high), proxy-addr (critical)**. This is historical registry evidence, not a new scan or confirmed application exploitability. This release is not a dependency-security remediation release. Those advisories require separate maintenance and isolated regression validation.

Advertisement snippets intentionally execute trusted administrator code. Same-origin compatibility iframes can access the parent origin and are **not security sandboxes**. Only configure trusted platform snippets and use a strong administrator password with restricted administrative access.

## Upgrade

1. Back up `data/settings.json` and `.env` under the deployment's existing backup policy. Neither operational file is shipped in the source archives.
2. Open the administrator's Online Update panel and update to **v1.1.13**, or use the README's release-tag procedure. Upgrade both backend and frontend; updating only static assets leaves old servers unable to persist or expose sidebar slots.
3. Restart Node/PM2 so the new backend defaults and slot projection take effect. PM2-managed online updates normally restart automatically; verify success. No new production dependencies are required.
4. Refresh administrator and frontend pages to load the versioned assets. Existing advertisement values remain intact, and both new sidebar slots start disabled.
5. For repeated ordinary code, choose **automatic** or **iframe compatibility**, not explicit inline. If different snippets still share global state, explicitly choose iframe. Choose HTML for full script-tag snippets and plain JavaScript only for code without script tags.
6. Enable left/right slots independently with suitable vertical creatives and verify on a desktop viewport at least 1500px wide. Result advertising requires a successful query. AdSense/GPT and other page-integrated SDKs must follow their providers' unit/container requirements; automatic isolation cannot override inventory, account, domain or repeated-unit policy.
