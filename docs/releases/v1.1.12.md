# v1.1.12 - Advertising integration fixes

## Changes

- Fix advertisement initialization inside hidden containers and execution order between classic external scripts and inline initialization. Preserve explicitly asynchronous scripts and module execution.
- Initialize result advertising after query results become visible, without creating repeated impressions on every query.
- Add HTML / plain JavaScript code types, automatic / inline / iframe compatibility modes, and parser-based legacy `document.write` handling with automatic iframe height adjustment.
- Validate advertisement slot names, flags, types, modes and per-slot 64K-character code limits before saving. Increase the JSON body cap to support complete multilingual advertising configuration.
- Keep administrator/provider settings out of the public advertising projection, preserve Head snippet dollar sequences, and disable dynamic configuration/page caches. Version local static assets consistently.
- Preserve existing JSON settings through default-field migration. No runtime production dependencies are added or upgraded; Playwright is development-only.

## Functional Evidence

The implementation development pass completed **6 Node interface/configuration tests and 11 Playwright browser tests**, including desktop/mobile advertising, administrator save/reload/application, ordered/asynchronous/module scripts, legacy iframes, disabled slots, result lifecycle and error isolation. The final narrow-mobile administrator save/application test was also rerun successfully.

These checks use disposable dummy configuration and mocked upstream responses. They do not prove live provider fill or production deployment behavior. They ran before the release version/cache/documentation-only changes. Final package version and source/archive identity are separately verified without executing application code.

## Security Review and Known Limits

A quick, partial source-only advertising audit used four reconnaissance readers, two hunters and one final coverage critic. No new confirmed security finding survived in the scoped advertising paths. The report records 5 source-covered units, 1 blocked final-artifact identity unit, 1 deferred pre-authentication JSON-capacity unit and 1 out-of-scope legacy unit. The separate publication procedure resolves artifact identity, but does not claim to resolve hosted tag-protection policy.

The required OS-isolated runtime security environment was unavailable. No target code was executed during the audit; ordinary functional tests are not penetration-test evidence. Unchanged provider rendering, password/default/fallback lifecycle, deployed TLS/proxy/CSP and updater internals were outside this partial pass. The global 2MiB JSON parser runs before authentication and requires a dedicated bounded capacity review before claiming coverage.

The production dependency scan still reports **4 pre-existing transitive advisories: body-parser (low), qs (moderate), path-to-regexp (high), proxy-addr (critical)**. Production dependency versions are unchanged. These registry severities do not establish exploitability in this application; nevertheless this patch is **not** a dependency-security remediation release or a clean full-product security certification. Resolve dependencies and validate the resulting runtime in a separately isolated maintenance pass.

Advertisement code is intentionally trusted administrator code. The same-origin iframe is compatibility isolation, not a sandbox against untrusted creatives. Only paste trusted platform snippets; use a strong administrator password and restrict administrative access appropriately.

## Upgrade

1. Back up `data/settings.json` and `.env` using the deployment's existing backup policy. They are ignored by Git and are not release artifacts.
2. In the administrator panel, open **Online Update**, check for `v1.1.12`, and update. The release uses the same official-tag mechanism as previous versions.
3. Restart Node/PM2 so the updated `server.js` and new `lib/ads.js` take effect. PM2-managed online updates normally restart automatically; verify the process returns successfully. No new production packages are required for this patch.
4. Refresh both administrator and frontend pages. Keep the complete new `public/js/ads.js` asset; updating only HTML/JS while leaving the old backend is not a supported partial upgrade.
5. Existing advertisements default to HTML / automatic mode. For code without script tags choose plain JavaScript; for external legacy document.write loaders choose iframe mode. Head is invisible; result advertising appears only after a query succeeds.

For manual source updates, follow the README's release-tag deployment procedure. Running development/browser tests requires Node.js 20+ and development dependencies; production can continue using the documented existing runtime.
